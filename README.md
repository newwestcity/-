# 每日阅读精选与 GitHub 学习周刊

每天北京时间 **08:00** 推荐适合认真阅读的内容：X 目标最多10篇，另加雪球金融阅读推荐3–4篇（条）。每周日北京时间 **08:00** 单独发10个GitHub学习项目。中英文来源均用中文导读，附原文链接、为什么读和能学到什么，不转载原文。数量是目标；缺少合格来源时如实少发，没有合格内容时生成`no_material`状态报告、不发空邮件，且保留后续补跑资格。

X优先科技、AI、金融的长帖、深入讨论和实践教程，也保留读书、大学生权益。雪球侧重价值投资、企业经营、财务与估值、行业研究和风险管理，不选K线、短线喊单或带单。GitHub优先 **AI应用、自动化、实用工具，语言不限**，要求有实际代码、明确许可证和快速开始说明。

原有可回退版本为 **`v0.1.0-demo`**，升级示范版保存为 **`v0.2.0-demo`**。2026-10-23的2条雪球链接示范已被QQ服务器接受；GitHub周刊已有5项实际预览，目标10。X仍受Tokeness渠道暂不可用影响。最新实测和恢复入口见 [PROJECT_STATUS.md](PROJECT_STATUS.md)。既有API密钥、QQ SMTP已经配置成功，升级不需要重新填写。

## 筛选依据

每篇文章先有真实来源和可读取的原文，再做中文评审。来源链接必须出现在搜索工具的独立元数据中；模型自己写出的链接不能入选。邮件显示评分分项、具体推荐理由和2–3个学习点。

| 文章维度 | 分值 | 看什么 |
| --- | ---: | --- |
| 论证深度 | 30 | 是否有完整问题、推理和分析，而非一句观点 |
| 正文证据 | 25 | 是否提供数据、案例、原始资料或可检查的依据 |
| 学习价值 | 25 | 能否学到方法、原理或可迁移的实践 |
| 可读性 | 10 | 解释是否清楚、结构是否适合阅读 |
| 当前适用性 | 10 | 是否仍值得读，是否已过期 |

程序要求总分至少75，深度至少18，学习价值至少15。编辑须逐字引用所收到正文中的依据；文章或项目中单条字段或依据不符时只拒绝该条，其他有效材料可以保留；响应结构错误则拒绝本次评审。分数是模型编辑的判断，不能当作作者论断已经证实。X同作者最多2篇、每类最多3篇；雪球同作者最多1篇。纯快讯、广告、短观点、诈骗、政治攻击和辱华内容排除；账号屏蔽见 [settings.json](settings.json)，目前未做完整账号历史审查。

X普通内容最近7天，学生优惠最近72小时。雪球普通文章最近30天，以适合读金融分析为主。股市、投资、读书及雪球长期原理可选经典，**每天两来源合计最多3篇**；旧行情、旧财报时点判断、旧产品消息和过期优惠不算经典。原文日期未知的雪球最多1篇，计入这3篇例外额度，并明确标注日期未确认。

X通过官方oEmbed读取正文摘录，**并不保证拿到完整长帖或整条讨论串**；摘录不足以支撑导读时拒绝，不凭开头编造全文。雪球正文只能采用身份一致的官方文章，风控页不当正文。

用户已明确选择雪球降级方式：遇到风控等读取障碍，允许提供**搜索工具真实返回的原文链接与标题**。邮件逐条标注“未读取全文、未做深度评分、原文日期未确认”，不生成全文摘要、作者介绍或学习结论。标题与原文链接之外的模型猜测不能进入候选；404、身份不符、正文太短等不能降级入选。每期雪球正文与链接合计最多4条、同作者ID最多1条。标题链接单独标记为未核实的阅读线索，不占已评审经典正文的3个名额；能读正文的文章不会因评分不合格而绕回标题候选。开关见`reading.xueqiu_link_fallback`，已按用户选择开启。无独立搜索标题时继续跳过，不能编造。

GitHub项目评分为可学性30、可复刻性30、实用性20、热度10、维护10；总分至少75，前两项各至少18。同一所有者最多2个。读取官方仓库信息和README，排除fork、归档、无明确许可证、纯资料列表和缺少启动说明的项目。每个项目给学习点、前置条件、难度、预计工作量和3步复刻建议；**未实际安装运行**。热度依据当前stars、forks和最近7天活跃情况，作为热门候选代理；没有实测历史快照时不宣称“本周涨星榜”。

## 使用

Python 3.12，Linux/macOS，仅标准库，无需安装依赖。导入包或查看帮助不会调用服务。

```bash
python -m unittest discover -s tests -q
python -m x_digest --check --send
python -m x_digest --fetch                         # 日报预览，可能计费
python -m x_digest --fetch --edition weekly        # 周刊预览，可能计费
python -m x_digest --fetch --send                  # 实际发送日报
python -m x_digest --fetch --edition weekly --send # 实际发送周刊
```

`--check`只检查配置，不联网、不发信。预览保存在`.local/preview/digest.html`，不记录为发送成功。正式发送先在持久账本预留本期；SMTP接受后才转为已发记录。同日的日报与周刊分开记账：日报每日一次，周刊每个ISO周一次；手动发正式周刊会占用该周的发送名额。已发版次的正式发送直接跳过；明确选择预览仍会执行检索，可能计费。

每次日报最多6次X来源搜索＋2次雪球来源搜索，最多20条X摘录和12篇雪球原文，至多4次普通编辑调用。每个领域至多一次API搜索请求，最多1500输出token，无自动重试。中转站不接受`max_tool_calls`，因此该配置只限制本地请求预算，不能硬限制服务端内部搜索次数。周刊最多3次GitHub API搜索＋20次README读取＋2次模型编辑（每批5个，最多并行2批），不运行候选代码。只在原文核验后调用编辑；失败的来源不阻断其他有效来源。X各分类即使部分成功也保留失败码和耗时；正文过短、编辑选空、评分不足分别计数。预览和发送分别执行会分别产生调用；工具和token限制不是金额上限。

## GitHub Actions

[每日阅读与GitHub周刊](.github/workflows/daily-digest.yml)部署在默认分支。主计划UTC `0 0 * * *`，另在北京时间09:17、10:17、14:17补跑；已发则在调用模型前跳过。每天最多4轮，每轮预算独立；全部失败时最多32次来源搜索、16次普通编辑。周日同一次计划串行处理日报和周刊，某一期失败仍继续另一期；不再用两个同时间cron竞争等待名额。计划按执行时的上海日期生效，运行窗口08:00–20:00，跨到周一不冒充上周周刊。GitHub排队和搜索耗时可能使实际到信晚于08:00；最近两次曾晚触发约2小时41分/45分，不能保证准点到信。普通代码推送只跑测试。

进入 **Actions → 每日阅读与 GitHub 周刊 → Run workflow**，选择`daily`或`weekly`；不勾选`send_mail`只生成预览，勾选则真实发信。HTML在运行详情的Artifacts下载。

已有配置继续使用：

| GitHub位置 | 名称 | 用途 |
| --- | --- | --- |
| Secrets | `DIGEST_API_KEY` | Tokeness API密钥 |
| Secrets | `SMTP_AUTH_CODE` | QQ SMTP授权码，不是登录密码 |
| Variables | `SMTP_USERNAME` | 发件QQ邮箱 |
| Variables | `MAIL_TO` | 可省略，默认发给自己 |
| Variables | `DIGEST_API_BASE` | 可省略，默认`https://n.tokeness.dev/v1` |
| Variables | `DIGEST_MODEL` | 可省略，默认已验证的`gpt-6-luna` |
| Variables | `DIGEST_ENABLED` | 未设置或true开启；false暂停所有定时投递 |
| Variables | `GITHUB_WEEKLY_ENABLED` | 未设置或true开启周刊；false只暂停周刊 |

读取GitHub项目只需只读token；正式投递任务另申请`contents:write`，仅用于独立的`digest-delivery-state`账本分支，无需新增密钥。普通编辑用`/chat/completions`，来源发现用`/responses`的`web_search`。密钥不写仓库、日志或聊天。程序不自动读取`.env`。

[完整预览](.github/workflows/check-digest-preview.yml)可分别检查日刊、周刊；[公开来源检查](.github/workflows/check-reading-sources.yml)不调用模型或SMTP，直接诊断GitHub、雪球和实验RSS来源。RSS实际未返回合规雪球链接，未纳入生产来源。API、X搜索、SMTP的旧单项检查仍保留，已通过的基础配置无需反复重做。

正式投递以独立`digest-delivery-state`分支的`reading-ledger.json`为权威账本，记录版次、日期和公开内容ID，默认90天去重、保留180天记录，不存邮箱和密钥。旧X/v2历史已由上线验收迁入。缓存只作本地副本；缺失或损坏可从权威账本恢复。生产账本缺失、读取失败或SHA冲突时停止发信，禁止悄悄重建空历史。

发信前持久登记pending，SMTP接受后转为已发；明确拒绝会解除本次预留，断连或超时等不确定结果保留pending并阻止同一期自动重发，须先核对收件箱和账本。SMTP不提供严格的恰好一次事务，不能保证崩溃时既不重复又一定补送。

`.local/reading-reserve.json`单独缓存最多120条已核验、未发送的备用材料，内容均为公开导读字段，不含原文或凭据。实时检索不足时重新检查身份、日期、质量和去重后补用；过期新闻不转成经典，学生优惠最多72小时，雪球标题与日期不明正文最多保存48小时，经典核验快照最多30天。邮件明确标出备用阅读。备用缓存丢失只减少候选，不影响已发账本；首次储备为空时无法弥补持续搜索故障。

零材料属于业务状态`no_material`，不发信、不记已发，并生成`status-report.json`、可查看的状态页和来源审计。生产工作流发警告，后续时段继续补跑；配置、认证、账本、文件和SMTP异常仍按失败处理。严格完整预览在零材料时仍返回非零，防止把无内容当成预览成功。失败时也保存诊断工件。

云开发环境用来改代码；定时任务运行在GitHub，不依赖Codex环境配置页面的“发布”。当前云执行机无法直连Tokeness/GitHub API，实际来源和模型检查在GitHub runner运行。原生Git推送已可用。
